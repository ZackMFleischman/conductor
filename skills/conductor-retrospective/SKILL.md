# Learn from reported problems

Read [retrospective commands](../conductor-work/references/retrospective-commands.md). Use the installed registry and a distinct live session. Reporting and analysis work without a team or planning policy. A review request authorizes analysis, not arbitrary changes to shared tooling or instructions.

Read reports and follow-ups within the requested project/scope and snapshot boundary. Preserve original observations. Group incidents by evidenced cause, distinguish facts from hypotheses, and cite exact report/event revisions. Insufficient evidence is a valid finding. Check existing open remedies before creating work; several incidents may belong to one ticket.

For each reviewed item record the rationale and disposition: prepare a remedy now, defer to a specific milestone with a revisit deadline, or observe with a stated trigger/deadline. Use the durable decision/coverage operations. Advance a processing checkpoint only after decisions and links are saved; retry ambiguous responses with the same request ID and payload. Do not destructively consume reports or let a follow-up to an older report disappear behind a creation-time cursor.

When authorized, create/link improvement tickets under the project's persistent Workflow Improvements epic. They are ordinary tickets without planning policy, or gated drafts where policy is configured. Include expected behavior, evidence, proposed scope, acceptance criteria, and how a fresh worker will test improvement. Use the normal work queue: the orchestrator schedules work when a managed team exists; otherwise hand it to the user or authorized standalone agent. Review-only work saves findings without creating implementation obligations. Milestone release records actual evidence and follows current standalone or coordinator authority; releasing a deferral does not itself satisfy planning gates.

Assess delivery and effectiveness separately. Link changed commits and validation to subsequent observations, including recurrence. A closed remedy is not proof of success; a recurrence requires a fresh decision rather than suppression as a duplicate. Do not claim a single successful repeat establishes permanent effectiveness.
